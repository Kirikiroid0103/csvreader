# CSV Viewer

Клиентское веб-приложение для загрузки и анализа CSV-файлов.
Ссылка на репозиторий:
https://github.com/Kirikiroid0103/csvreader

## Возможности
- загрузка CSV через кнопку выбора файла и drag'n'drop;
- автоматическое определение разделителя: `,`, `;`, `\t`, `|`;
- определение типов столбцов: числовой, категориальный, дата, смешанный;
- сводка: строки, столбцы, пропуски, файл;
- аналитика:
  - числовые: среднее, медиана, минимум, максимум, стандартное отклонение, пропуски;
  - категориальные: уникальные значения, пропуски, топ-5 по частоте;
- визуализация:
  - числовые: столбчатая диаграмма метрик;
  - категориальные: топ-5 значений с барами;
- фильтры:
  - по категориальному столбцу и значению;
  - по числовому столбцу и диапазону;
- таблица первых 20 строк с горизонтальной прокруткой;
- адаптивная вёрстка до 360 px;
- понятные сообщения об ошибках;
- валидация файла перед аналитикой:
  - пустой файл → ошибка;
  - битый CSV (незакрытые кавычки, несовпадение числа полей) → ошибка;
  - файл без числовых столбцов → ошибка;
  - текст вместо чисел в числовых столбцах → ошибка;
  - пустые строки и пропущенные значения → предупреждение (аналитика выполняется).

## Запуск
Проект полностью клиентский. Можно открыть `index.html` в браузере.

Для кнопки «Загрузить пример» рекомендуется запустить локальный сервер, потому что `fetch` локальных файлов может быть ограничен при открытии через `file://`.

Пример:
```bash
git clone https://github.com/Kirikiroid0103/csvreader
cd csvreader
python -m http.server 8000
```
Затем открыть:
```
http://localhost:8000/
```

## Что пришлось исправлять за ИИ и как вы поняли, что там ошибка;
После рефакторинга часть функций перестала работать, проверил в браузере работоспособность. У модели нет собственного компьютерного зрения - пришлось просить разместить элементы иначе, настроить масштабирование или добавить какую-то дополнительную информацию на графики, это стало понятно посмотрев на страницу с точки зрения бизнес-аналитика.
## Что не успели или сделали бы иначе при наличии времени.
Чтобы не терять контекст при достижении лимита сообщений в чате или при автокомпакте следовало создать документ сессии с кратким описанием контекста, например: что было сделано, что было, что еще предстоит сделать. 2. Пошаговый план выполнения (ориентир на 1 день)
Этап 1: Подготовка данных (30 мин)
Задание требует минимум 100 строк, 5 столбцов, 2 числовых + 2 категориальных. Проще всего сгенерировать CSV через ИИ (промпт: «Сгенерируй CSV с 150 строками продаж: product, category, price, quantity, date, region, rating, id. Сделай 20% пропусков в rating и пару битых строк для теста»). Сохраните как sales_data.csv — это часть сдачи.

Этап 2: Каркас и загрузка файла (1–1.5 часа)
Промпт для ИИ: «Создай HTML-страницу с drop-зоной и кнопкой выбора CSV. Подключи PapaParse через CDN. После загрузки покажи таблицу первых 20 строк с горизонтальной прокруткой и сводку (строки, столбцы, пропуски, типы)».

Что проверить: автоматическое определение типов — ИИ может ошибиться, считая числовой столбец категориальным, если в нём есть пропуски. Проверьте на своём CSV с пропусками.

Этап 3: Аналитика (1 час)
Числовые столбцы: среднее, медиана, min/max, stddev, пропуски. Категориальные: unique + топ-5.
Подводный камень: медиана и stddev для столбца с пропусками. ИИ может предложить d3.mean или самописную функцию — проверьте, что пропуски игнорируются, а не превращаются в 0.

Этап 4: Визуализация + интерактив (2–3 часа)
Три графика (гистограмма, круговая/столбчатая, scatter) с выпадающими списками. При смене столбца — перерисовка без перезагрузки.

Критичная проверка: при повторной загрузке другого файла старые графики должны уничтожаться (Chart.js требует chart.destroy() перед созданием нового). ИИ часто забывает это, и графики накладываются.

Этап 5: Обработка ошибок и адаптив (1 час)
Проверьте сценарии, которые требует задание: пустой файл, битый CSV, файл без числовых столбцов, текст вместо чисел. Вместо пустого экрана — понятное сообщение.
Адаптив: на ширине 360px таблица не должна ломать вёрстку — достаточно overflow-x: auto на контейнере.

Готово! Проанализировал проект CSV Viewer и добавил полноценную обработку ошибок.

Что было сделано
Новый файл js/validation.js — модуль валидации, который проверяет файл до запуска аналитики:

Случай	Поведение
Пустой файл (0 байт / только пробелы)	Ошибка: «Файл пуст. Загрузите CSV с данными.»
Битый CSV — незакрытые кавычки	Ошибка: «Битый CSV: обнаружены незакрытые кавычки»
Битый CSV — несовпадение числа полей	Ошибка: «в N строк(ах) число полей не совпадает с числом заголовков»
Файл без числовых столбцов	Ошибка: «В файле нет числовых столбцов. Аналитика невозможна.»
Текст вместо чисел в числовых столбцах	Ошибка: «В числовых столбцах обнаружен текст вместо чисел: «Продажи» (1 знач.)…»
Только заголовки, без данных	Ошибка: «Файл не содержит строк данных — только заголовки.»
Пустые строки	Предупреждение: «Обнаружено пустых строк: N»
Пропущенные значения	Предупреждение: «Строк с пропущенными значениями: N (всего пропусков: M)»
Изменения в js/app.js — валидация вызывается в loadFile() и loadSample(): при ошибке аналитика не выводится, в статусе показывается сообщение об ошибке; при предупреждениях они добавляются к статусу загрузки.

index.html — подключён validation.js после data.js.

README — обновлены описание возможностей и таблица ожидаемого поведения тестовых файлов.
